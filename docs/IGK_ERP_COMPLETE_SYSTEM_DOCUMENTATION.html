1. Executive Summary & Architectural Philosophy

The IGK School Management System (SMS / ERP) represents an institutional software engineering achievement designed to centralize and automate every operational, academic, financial, and logistical workflow of modern educational institutions. Operating on Laravel 12.71.0 and PHP 8.2+, the platform provides strict tenant isolation across multiple branch campuses, fine-grained role-based access control, double-entry general ledger accounting, automated fee billing, and real-time statutory reporting.

Architectural Philosophy: Native Convention Over Unnecessary Abstraction
The engineering architecture purposefully rejects artificial abstraction layers such as "Repository Pattern", "Data Transfer Objects (DTO)", or "Action Classes" which often cause bloated codebases in PHP web applications. Instead, the application leverages native, battle-tested Laravel patterns:
  • Thin Controllers: Exclusively handle HTTP requests, input injection, and view rendering.
  • Form Requests: Strictly enforce input validation rules and Spatie authorization policies before controller invocation.
  • 24 Domain Services: Encapsulate multi-step business transactions within atomic database transactions (DB::transaction).
  • Rich Eloquent Models with Global Scopes: Enforce multi-campus isolation at the SQL query level via BranchOwned scopes.
  • Decoupled Queue Workers: Asynchronously execute heavy operations (monthly payroll runs, GPA generation, and bulk CSV parsing).

4. Core Mathematical Engines & Business Logic Invariants

The IGK ERP maintains mathematical precision and database consistency through rigorous business invariants enforced at the database and service layers:

4.1 Gapless Sequential Numbering Engine

Every commercial invoice and official cash receipt requires an uninterrupted, sequential serial number compliant with national auditing standards. The NumberSequenceService implements row-level locking via pessimistic locks (SELECT FOR UPDATE) within an atomic database transaction:

// app/Services/NumberSequenceService.php
public function next(string $seriesKey, ?int $branchId = null): string
{
    return DB::transaction(function () use ($seriesKey, $branchId) {
        $sequence = NumberSequence::where('series_key', $seriesKey)
            ->where('branch_id', $branchId)
            ->lockForUpdate()
            ->firstOrFail();

        $sequence->current_number++;
        $sequence->save();

        return sprintf('%s-%s-%06d', $sequence->prefix, date('Y'), $sequence->current_number);
    });
}

Invariant: Race conditions are impossible even under concurrent cashier checkouts, preventing duplicated or skipped receipt numbers.

4.2 Double-Entry Accounting Invariant ($\sum \text{Debits} = \sum \text{Credits}$)

Financial transactions must strictly balance across journal lines before persistence. The JournalEntryService validates equality down to 2 decimal places using arbitrary-precision BCMath:

// Validation Invariant in JournalEntryService.php
$totalDebit = '0.00';
$totalCredit = '0.00';

foreach ($lines as $line) {
    $totalDebit = bcadd($totalDebit, (string)$line['debit'], 2);
    $totalCredit = bcadd($totalCredit, (string)$line['credit'], 2);
}

if (bccomp($totalDebit, $totalCredit, 2) !== 0) {
    throw new UnbalancedJournalException("Debits ({$totalDebit}) do not equal Credits ({$totalCredit}).");
}

4.3 Attendance 48-Hour Tamper-Proof Lock

To eliminate retrospective grade manipulation and falsified attendance records, attendance sessions transition into a read-only locked state exactly 48 hours after creation:

// app/Services/AttendanceSessionService.php
if ($session->created_at->diffInHours(now()) > 48) {
    throw new AttendanceSessionLockedException("This attendance session was locked after 48 hours and cannot be modified.");
}

4.4 Statutory Payroll Deductions (EPF & ETF Invariants)

Payroll computation follows statutory Sri Lankan labor compliance standards:

  • Employee EPF (8%): Deducted from employee basic gross: $\text{EPF}_{\text{employee}} = \text{Basic} \times 0.08$.
  • Employer EPF (12%): Employer institutional contribution: $\text{EPF}_{\text{employer}} = \text{Basic} \times 0.12$.
  • Employer ETF (3%): Trust fund institutional contribution: $\text{ETF} = \text{Basic} \times 0.03$.
  • Net Pay Invariant: $\text{Net} = \text{Basic} + \text{Allowances} - (\text{EPF}_{\text{employee}} + \text{Deductions} + \text{Taxes})$.

4.5 Exam Grading & Cumulative GPA Calculation

Exam papers are converted to letter grades and grade points ($GP \in [0.0, 4.0]$) via custom institution grade scales. Cumulative Grade Point Average (CGPA) is computed as:

$$\text{CGPA} = \frac{\sum_{i=1}^n (\text{GradePoint}_i \times \text{CreditHours}_i)}{\sum_{i=1}^n \text{CreditHours}_i}$$

8. The Master Troubleshooting Handbook & Error Resolution Guide for Sir

This operational manual provides Academic Directors ("Sir") and lead engineers with immediate diagnostic scripts, root cause analyses, and terminal one-liners to fix any system runtime error:

Fault 01: HTTP 403 Forbidden - Role Permission Unauthorized / Cross-Branch Data Trap CRITICAL
Symptom & Visual Failure:
User clicks a sidepanel link (e.g. Invoices or Student Creation) and is abruptly blocked with an HTTP 403 Forbidden screen: "User does not have the right permissions" or "Cross-branch access violation."

Root Cause Analysis: The user account is missing the required Spatie permission token in `model_has_permissions`, or the record being accessed belongs to Branch B while the user is scoped to Branch A under the `BranchOwned` global scope.

Diagnostic Artisan / Terminal Script for Sir:
php artisan tinker --execute="
$u = App\Models\User::where('email', 'target_user@example.com')->first();
dump('Assigned Roles:', $u->getRoleNames());
dump('Assigned Permissions:', $u->getAllPermissions()->pluck('name'));
dump('Assigned Branch ID:', $u->branch_id);
"
Exact Resolution & Auto-Fix Script:
php artisan tinker --execute="
$role = Spatie\Permission\Models\Role::findByName('Registrar');
$role->givePermissionTo('students.create');
app()->make(\Spatie\Permission\PermissionRegistrar::class)->forgetCachedPermissions();
echo 'Permission granted and cache purged successfully.';
"

Preventive Invariant Enforced: Always run RolePermissionSeeder when deploying schema updates. Ensure users created at branch level have correct branch_id.

Fault 02: PaymentExceedsBalanceException (422 Unprocessable Entity) HIGH
Symptom & Visual Failure:
Cashier enters a fee collection amount against an outstanding invoice, but form submission fails with error: "Payment amount exceeds the invoice balance."

Root Cause Analysis: The invoice has already received partial payments or discounts, leaving a balance less than the entered payment amount. Invariant: `amount <= invoice.balance`.

Diagnostic Artisan / Terminal Script for Sir:
php artisan tinker --execute="
$inv = App\Models\Invoice::where('invoice_number', 'INV-2026-000045')->first();
echo 'Invoice Total: ' . $inv->total . ' | Paid: ' . $inv->amount_paid . ' | Remaining Balance: ' . $inv->balance;
"
Exact Resolution & Auto-Fix Script:
php artisan tinker --execute="
// Instruct cashier to collect <= remaining balance, or if balance is corrupted due to direct manual SQL edits:
$inv = App\Models\Invoice::where('invoice_number', 'INV-2026-000045')->first();
$actualPaid = App\Models\Payment::where('invoice_id', $inv->id)->sum('amount');
$inv->amount_paid = $actualPaid;
$inv->balance = bcsub((string)$inv->total, (string)$actualPaid, 2);
if ($inv->balance <= 0) { $inv->status = 'paid'; }
$inv->save();
